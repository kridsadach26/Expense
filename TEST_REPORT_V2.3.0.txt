สถานการณ์ที่ออกแบบและตรวจตรรกะ:
1. A ต้องจ่าย C 100, B ต้องจ่าย C 50
   - บันทึก A -> C 40 => A เหลือ 60, B เหลือ 50, C เหลือรับ 110
2. ชำระบางส่วนแล้วชำระเต็มส่วนที่เหลือ
   - ระบบลดยอดค้างทันทีและรายการเดิมหายเมื่อเคลียร์ครบ
3. เลือก debtor คนอื่นจ่ายให้ creditor คนเดิม
   - รองรับตราบใดที่ผู้จ่ายยังมียอดต้องจ่ายและผู้รับยังมียอดต้องรับ
4. สลับผู้จ่าย/ผู้รับผิดทิศทาง
   - ระบบแจ้งว่าไม่ใช่ทิศทางยอดค้างและปิดปุ่มบันทึก
5. กรอกยอดเกินยอดสูงสุดของคู่ชำระ
   - ป้องกันการบันทึก
6. ยกเลิกรายการชำระ
   - เก็บประวัติเป็น void และคืนยอดค้างให้โดยอัตโนมัติ
7. โปรเจกต์ทริปที่มีเงินกองกลาง
   - Settlement ถูกใช้หลังคำนวณเงินส่วนตัว + contribution + custody แล้ว จึงไม่ทำให้กองกลางหรือค่าใช้จ่ายถูกนับซ้ำ
8. โปรเจกต์ปิดแล้ว
   - ยังบันทึกการเคลียร์ยอดได้ เพราะมักชำระหลังจบทริป
9. โปรเจกต์ยกเลิก
   - ป้องกันการเพิ่มการชำระใหม่

หมายเหตุ:
- การชำระระหว่างสมาชิกเป็น ledger settlement ไม่ใช่ income/expense
